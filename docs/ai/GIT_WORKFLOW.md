# Git 与远程仓库治理规范

## 1. 仓库根目录

- 唯一仓库根：`{{SOURCE_ROOT}}`。
- 运行目录、发布产物、实验材料和客户数据目录不是源码仓库。
- 开始前验证 `git rev-parse --show-toplevel` 的结果符合预期。

## 2. 远程仓库内容边界

允许进入 Git：源码、必要配置模板、测试、迁移、文档和可重复构建脚本。

禁止进入 Git：

- 密钥、令牌、生产证书私钥；
- 客户数据库、WAL/SHM、录像、图片和日志；
- 本机运行时、缓存、虚拟环境、依赖目录和构建产物；
- 未经许可的大模型、二进制依赖和第三方受限文件；
- 含个人绝对路径或账号信息的本机配置。

## 3. 分支策略

| 分支类型 | 命名 | 用途 | 合并要求 |
|---|---|---|---|
| 主分支 | `{{main}}` | 可发布基线 | 保护、评审、检查通过 |
| 功能 | `feature/{{name}}` | 新功能 | 测试与文档同步 |
| 修复 | `fix/{{name}}` | 缺陷修复 | 回归测试 |
| 发布 | `release/{{version}}` | 可选发布准备 | 只允许发布相关修改 |

## 4. Commit 规则

- 一个提交表达一个可说明的意图。
- 不使用 `git add .` 掩盖范围；优先暂存明确文件。
- 提交前检查 `git status`、`git diff`、`git diff --cached`。
- Commit message 推荐：`type(scope): summary`。
- 未经明确授权不提交、不 push、不 tag、不创建 Release。

## 5. Push 前报告

- 当前分支和目标远程分支；
- 将推送的 commit；
- 修改文件与测试结果；
- 未提交修改；
- 大文件、运行数据、数据库和秘密信息扫描结果；
- 是否涉及版本、迁移、发布或兼容性破坏。

## 6. 版本与发布约束

- 版本号唯一来源：`{{VERSION_SOURCE}}`。
- 正式构建记录 commit、分支、构建时间、产物类型和 dirty 状态。
- 正式发布默认来自 clean worktree。
- 测试产物如允许 dirty，必须显式标识，不得冒充正式发布。
- 禁止维护多套人工版本号。
