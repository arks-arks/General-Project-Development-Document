# Build, Deployment and Release

> 用途：给出可重复、可追溯、可回滚的构建和发布流程。

## Source / Runtime / Artifact 边界

| 类型 | 位置 | 内容 | 禁止内容 |
|---|---|---|---|
| Source | `{{SOURCE_ROOT}}` | 源码、测试、文档、构建脚本 | 客户数据、密钥、运行缓存 |
| Runtime | `{{RUNTIME_ROOT}}` | 当前运行所需文件 | 开发工具、测试数据 |
| Full | `{{FULL_PATTERN}}` | 完整独立运行包 | Git、测试、客户数据、私钥 |
| Update | `{{UPDATE_PATTERN}}` | 最小替换载荷 | 客户 data、runtime、无关模型 |

## 发布前置条件

- [ ] 版本号来自唯一来源 `{{VERSION_SOURCE}}`。
- [ ] Git worktree 符合 clean/允许 dirty 策略。
- [ ] 依赖锁定并可追溯。
- [ ] 必需测试达到发布门槛。
- [ ] 数据迁移、兼容性和回滚方案已确认。
- [ ] 不包含密钥、客户数据和本机配置。

## 产物内容验证

- 必需文件存在；
- 禁止文件不存在；
- metadata 与目录名、版本、commit 一致；
- checksum 完整并可复核；
- Full/Update 配对来自同一版本与提交；
- 安装/更新不会覆盖客户数据；
- 产物在隔离目录中可启动或安装。

## 部署步骤

1. 核对目标环境与安全状态。
2. 记录当前版本、服务状态和关键数据状态。
3. 创建可恢复备份或快照。
4. 上传/复制并核对哈希。
5. 应用更新或替换文件。
6. 重启必要服务，不扩大影响范围。
7. 执行健康检查、协议检查和安全状态检查。
8. 失败时立即按回滚条件恢复。

## 发布完成标准

- 构建成功不等于发布完成。
- 只有产物验证、部署、健康检查、数据保护和所需 L3/L4 验证均满足门槛，才可声明对应范围发布完成。
